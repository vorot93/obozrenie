# Design

Obozrenie is a desktop server browser: adapters fetch server lists, core stores them, a display-free presenter decides what to show, and a GTK 4 window shows it and launches clients.

## Modules

| Module | Responsibility |
|---|---|
| `game_table` | `QueryStatus`, `GameTable` (the locked per-game store and its token-admitted queries), `validated_server_batch` |
| `core` | `Core`: owns the game table and geolocation it is given, admits and tracks query workers, launches games; `_QueryAttempt` is its single-completion handoff |
| `geoip` | database discovery and download, and `Geolocation`, the country lookup Core and the GTK offer share |
| `settings` | `Settings` and `COMMON_OPTIONS`, the persisted option names |
| `launch`, `ping`, `network_calls`, `http_client`, `qstat_processes`, `adapters/` | launching, RTT, bounded pools, HTTPS transport, QStat supervision, master-list adapters |
| `list_rows` | the `GObject` rows the lists render — `GameRow`, `ServerRow`, `PlayerRow` — and `country_code_to_flag_emoji` |
| `presenter` | the `MainView` protocol, `MainPresenter`, `derive_action_sensitivity`, the filter criteria, `ServerDetails`, `PreferenceField`, `OptionKind` and `game_options()` (the per-game option schema), and `COMMON_OPTION_ACCESSORS` |
| `gtk` | `App`: startup, activation, the startup-dialog chain, shutdown |
| `gtk_window` | `MainWindow`, the composite template that implements `MainView`: models, filters, sorters, selection, and the notifications it sends |
| `gtk_lists` | the list-item factories that render `list_rows` rows |
| `gtk_dialogs` | `load_template`, `present_error`, `ServerInfoDialog`, `present_about` |
| `gtk_preferences` | `PreferencesDialog`, built from the presenter's `PreferenceField`s |
| `gtk_geoip` | `GeoIPDownloadCoordinator` and `GeoIPOfferDialogs`, the dialog seam it drives |
| `gtk_icons` | packaged icons as `Gdk.Texture`s |
| `launch_gtk` | the `obozrenie-gtk` entry point, the toolkit floor, and `ApplicationServices` |

The domain modules never import `gi`; `list_rows` and `presenter` import only
`GObject` and `GLib`; only the `gtk*` modules import `Gtk`, `Gdk`, or `Adw` at
module level, and importing them needs no display. `launch_gtk` is the one
module outside that tier that names `gi` at all, and only inside
`_require_toolkit()`, so importing the launcher starts nothing.
The test suite relies on all three, and `tests.test_delivery` parses every
module's source to hold each tier to its own share of `gi`.

## Core

`Endpoint` is the canonical host/port value. Hosts are unadorned and whitespace-free, ports are explicit integers from 1 through 65535, and IPv6 is bracketed only when rendered.

Adapters and `GameTable` exchange transitively immutable records with exact-type constructor schemas: `Endpoint` has an exact `str` host and exact `int` port; `Player` has an exact `str` name, exact `int` or `None` score, and exact `int` ping; and `Server` has an exact `Endpoint`, exact scalar fields, a tuple of exact `Player` records, and read-only rules with exact `str` keys and exact `str`/`int`/`float`/`bool`/`None` values. Player counts alone are nonnegative; score and ping remain signed, and count does not have to fit the limit. Every record integer the UI renders — `Player.score`, `Player.ping`, `Server.player_count`, `Server.player_limit`, and `Server.ping` — must fit the signed 32-bit range `-2147483648`…`2147483647`, the domain of the `GObject.Property(type=int)` row properties in `list_rows`; `None` stays valid for `Player.score` alone, the two counts keep their nonnegative floor, and an out-of-range value raises `ValueError` instead of being clamped, so a hostile master response is isolated per record at the adapter and an all-invalid batch reaches `ERROR` before Core commits `READY`, rather than failing mid-render. Four of the five travel on such a property, which raises `TypeError` on a wider value; `PlayerRow.score` alone is an object property, which enforces nothing but lets a `None` score stay `None` and render as an empty cell instead of a fabricated zero. The records, not the properties, are therefore what hold all five to one domain. `Server` materializes the player iterable and copies the rules mapping before validation, so caller containers cannot alter a record. `Endpoint`, `Player`, and `Server` are final value-record classes created through a record metaclass from one non-final empty slotted base. The metaclass rejects class creation when any direct base is marked final, independent of mixin order or `__init_subclass__` cooperation; rebuilding a `slots=True` dataclass remains valid because dataclasses rebuild each concrete record from the non-final base. Defensive adapter, completed RTT, and storage boundaries accept only exact `Server` objects, and `Server.__deepcopy__` reuses only the exact final type. Nothing converts a record to a mutable copy: the presentation tier builds `list_rows.ServerRow` from the record's own fields.

`GameTable` holds per-game `info` (name, adapter, launch pattern, optional Steam app id), `settings`, servers, and query state behind one reentrant lock. `begin_query` admits one query per game and returns an opaque token minted for that admission, or `None` while a query is `WORKING`; the token is stored with the game entry. `finish_query` and `fail_query` take that token, materialize and exact-validate the complete server batch or require an exact immutable `str` error before locking, then commit only while the entry is still `WORKING` with that exact token, consuming the token as they publish `READY` or `ERROR`. Each reports that ownership as a `bool` instead of raising, so a stale attempt cannot mutate a later query even while that query is `WORKING`, and a rejected transition leaves old data, the stored error, and the running query untouched. No public status/server mutation bypass exists, and copy accessors safely reuse immutable server records.

`Core` owns the `GameTable` and `geoip.Geolocation` it is constructed with — the launcher loads the shipped `game_lists.toml` through `GameTable.from_shipped_list()` and discovers a MaxMind country database through `Geolocation.discover()` (system paths, then XDG cache) — and runs each admitted query on one daemon thread. Admission creates one query attempt for the token `begin_query` returned and hands it to the worker through a lock-protected one-shot handoff: the worker claims the attempt before it may report anything, and whichever side reaches the terminal state first performs the single token-aware `GameTable` transition and invokes the single callback, always after releasing the attempt lock, so no callback runs under a lock. A launch failure before that claim is the query's terminal failure and still reports the query as admitted; a launch failure after it only logs, because the worker already owns the outcome; a caller `BaseException` re-raises unchanged after the same cleanup. The worker rejects non-`Server` adapter and RTT results before enrichment, calls RTT once for each complete adapter batch, adds country data by immutable replacement, and atomically commits the complete list; RTT invocation or result-materialization failure falls back to a fresh copy of the untouched adapter batch, retaining its pings and order. An adapter or enrichment failure publishes one sanitized `ERROR` over preserved old servers, a worker `BaseException` publishes that same state once and then re-raises the same exception object, and a callback that raises is reported without disturbing the outcome it already published. Every Core diagnostic is the fixed text `diagnostics.diagnostic_for_exception` derives from an exception, never its stringification, written through `helpers.log_safe_diagnostic` — the one best-effort logger Core, the QStat adapter, and the GTK handler recorder share, which drops a report it cannot write — so a diagnostic that fails itself cannot change terminal query state or replace a primary failure.

Core owns every query it admits: one lifecycle lock guards the closing flag, the attempts that may still complete, and the worker threads that may still be running. Admission checks that flag and registers the attempt under that lock before any thread exists, and a constructed thread is bound and registered before it is started, so close cannot miss a partly launched query. `begin_close` marks Core closing and snapshots the active attempts under the lock, then cancels them outside it: cancellation terminalizes each attempt, publishes the sanitized `ERROR` over preserved old servers, and suppresses its callback. One attempt whose cancellation fails is reported safely and does not strand the rest, and an attempt is forgotten only once its cancellation has returned, so a close an interruption cut short leaves the remainder for the next one. Close also outranks the completion owner: the closing check and the `GameTable` transition share the lifecycle lock, so a transition either lands entirely before close began or never lands at all, and `begin_close` cannot return while one is in flight. No attempt can therefore publish once close has begun — the only state that lands then is close's own cancellation — and an attempt that won completion just before close keeps the state its game already had. One callback can still outlive close: an attempt decides inside that critical section whether it may call back and then calls outside it, as every callback must, so a callback whose commit was decided before close began may start, or still be running, after `begin_close` returns. What bounds it depends on which side owns the completion: a worker's callback runs on the tracked thread `join_until` joins, while the callback of a launch failure no worker ever claimed runs on the admitting caller's own thread, which Core never tracks and which `update_server_list` bounds by returning. No attempt decides to call back once close has begun. `join_until` validates the absolute deadline before it reads any thread state, then joins every tracked thread against that one unchanged deadline, recomputing each thread's remaining time, skipping a thread that has not launched, and releasing every thread it observes stopped; a worker releases its own attempt and thread registration when its target exits, and a launch that failed before the thread ran releases the thread it can prove never started. `close_until` validates the deadline, begins close, and joins; both halves are idempotent, so a repeated close retries the joins that did not complete without terminalizing anything a second time. Blocked daemon work may outlive the deadline, but it can no longer publish query state or start a callback.

`Core.start_game` resolves game metadata and settings, parses the complete endpoint, captures its own activation directory (`os.getcwd()`), and builds the complete `LaunchSpec` before constructing a daemon worker, so the worker only spawns what that snapshot already describes and never reads a process-wide working directory. Invalid games, endpoints, launch patterns, and missing or empty executable settings therefore cannot start launch work. An admitted worker reports the exact returned launch error, a raised ordinary exception, or `None` to its optional completion callback exactly once from a `finally` path.

`Settings` merges default TOML with the XDG config profile. User tables are
written through same-directory temporary files `fchmod`ded to `0600` through
their own descriptors, flushed and fsynced, then atomically replaced, so the
installed file carries that mode from the instant it appears under its name and
no umask can widen it. Nothing else touches the live pathname: a `chmod` on a
name could only act on whatever occupies it in that instant — a file another
process installed, or the target of a symlink it left there. Malformed bundled TOML,
including invalid UTF-8, remains fatal. `helpers.load_user_table` reads one
immutable byte snapshot of a user table — payload plus the device, inode, mode,
size, and nanosecond mtime of the descriptor it read from — and parses only that
snapshot. Malformed or invalid-UTF-8 bytes are copied into a private
same-directory `.invalid-*` sibling that `tempfile.mkstemp` allocates (no manual
collision loop), fchmodded to `0600`, written whole, flushed, fsynced, and
closed; only a partial backup whose name still holds the very file that call
created is removed when its write fails. The live pathname is never renamed,
unlinked, chmodded, or otherwise mutated, so a valid replacement written by
another process survives recovery. Currency is rechecked before and after
archiving: a source that changed is reread, at most three snapshots are
inspected, and a source that keeps changing raises
`RuntimeError("User settings changed during bounded recovery.")` without
touching it. Defaults are then loaded and one payload-free warning is returned
per recovered table; the next atomic save replaces the malformed file, so
backups do not accumulate across ordinary runs — a run that never reaches its
shutdown save (`App.on_shutdown` saves only from `status == "up"`) leaves the
malformed file in place and archives the same bytes again on the next load.
Missing user tables are normal and produce no warning. Every `OSError` on these paths is declared instead of propagated raw: a snapshot that cannot be read becomes `helpers.SettingsReadError` (`Settings file could not be read.`), a recovery backup that cannot be written becomes `helpers.SettingsBackupError` (`Settings backup could not be written.`), and any filesystem failure of a save becomes `helpers.SettingsWriteError` (`Settings file could not be written.`). Each suppresses an original that names the path and carries `errno`, and each is still an `OSError` for callers that read it as one. A signal handler cannot re-raise, so that declared text is the whole of what a failed load or save reports. Every rollback — `save_table`'s `finally`, the partial-backup removal, the sibling writer's own setup cleanup — is best effort: a declared write failure normally leaves no temporary sibling behind, and a rollback that itself fails (the directory's permissions changed underneath it) cannot replace the declared failure with its own.

One `filelock` lock per profile, at `<profile path>.lock` with mode `0600` and a
five-second acquisition bound, serializes settings operations across processes.
`Settings.load` holds it across both user-table reads and releases it before returning; `Settings.save` holds it across both atomic writes,
which it prepares beforehand. Acquisition that exceeds the bound raises the
payload-free `SettingsLockError` instead of spinning, so a contended profile
fails as a sanitized settings failure. Creating the lock file also makes a
writable profile *parent* directory a requirement of loading, not only of
saving: on a read-only parent, acquisition raises the raw `PermissionError`
from lock creation rather than a `SettingsLockError`. `App.on_shutdown` saves
before `services.begin_close()`, so that five-second wait sits on the shutdown
path ahead of the launcher's one-second service-join deadline; it is bounded and
accepted rather than deferred, because a save that loses its writes is worse
than a slow exit.

Common and per-game values load through declared-option whitelists, so legacy or
unknown keys are not retained or saved. The packaged common defaults match
`settings.COMMON_OPTIONS` exactly; per-game `nickname` remains a declared
option of the preferences schema (`presenter.game_options()`). The
password entry is transient GTK state and never enters
the settings table.
Before `load` returns, invalid browser and Connect game IDs normalize to the
configured game ordered by case-folded display name and ID; an empty game
configuration leaves both selectors empty. `MainPresenter.bind_settings` then
shows each common option through its view writer
(`presenter.COMMON_OPTION_ACCESSORS`), and `update_settings_table` copies
every accessor's value back as text on the three notifications that can
change one: `browser_game_changed`, `connect_data_changed`, and
`sidebar_toggled`.

## Bounded Network Calls

`network_calls` owns one process-wide, dynamically resolved registry of lazy fixed daemon pools: four DNS workers, four HTTP workers, and 32 ICMP workers. Each pool has equal worker, queue, and admission capacity and never starts replacement workers. Admission uses exactly that many identity tokens, an available-token set, and a token-to-current-call owner map under the pool lock. Owner-checked return publishes availability, clears ownership, and only then removes the supplied call from active state; retries are idempotent, and a stale queued call cannot return or remove a reassigned token's new owner. Submission construction, enqueue, synchronous map registration, and return form one guarded handoff. Any failure abandons and signals a possibly queued call and receives two cleanup attempts before escaping, so map cleanup already owns a call once registration has completed. Calls move through pending, running, completed, abandoned-pending, abandoned-running, or consumed under the sole pool-lock-then-call-lock order. Deadline, interruption, or close records and signals pending abandonment before returning its token, allowing timeout or close to recover even when a worker loses a dequeue result before assignment. Running abandonment remains worker-owned until finish or worker death. Repeated abandonment repairs a missing reason, preserves an existing reason, and re-signals completion. Completion publishes outcome, completed state, signal, and token return in that order; retry resumes a partial completed publication. Worker death clears a partial running outcome, but repairs the signal and token for an exact completed outcome instead of replacing it. Late values and exceptions are discarded. Other worker `BaseException` paths wake the caller with a fresh unavailable error, return and remove the owned call, and permanently retire that worker. Startup is serialized and sticky: the initiating raw caller receives the original construction/start exception, while later raw calls receive fresh payload-free unavailable errors. Close distinguishes immediate admission closure from completion of the cleanup transaction. Every incomplete attempt repairs active abandonment, drains queued work and old sentinels, rebuilds one stop sentinel per currently live launched worker, and marks completion only last. Registry close attempts every pool, retries each incomplete pool once, joins every pool to one original shared deadline, and then re-raises the first `BaseException`. All workers are daemon threads, so permanently blocked operations cannot delay interpreter exit.

`network_calls.validate_deadline` is the single absolute-deadline boundary. It accepts only exact finite `float` values whose positive remaining duration fits `threading.TIMEOUT_MAX`, returns the exact object unchanged, and accepts finite past deadlines for immediate expiry. `call_until` validates before submission, `map_until` before input materialization or startup, `getaddrinfo_many_until` before touching its host iterable or registry (including empty batches), and `BoundedCall.result_until` before waiting or changing call state, so malformed deadlines cannot start work or reach platform wait primitives. `ping.measure_rtt` and `add_rtt_info` validate the same way: a supplied deadline is checked before their endpoint or server iterable is consumed, an empty batch with no supplied deadline returns without reading the clock or the registry, and a nonempty batch with no supplied deadline computes and validates the five-second default only then.

| Service | Pool size | Shared caller deadline | Service error policy |
|---|---:|---:|---|
| DNS / GeoIP | 4 | 5 seconds per hostname batch | Resolver, hostname-encoding, MMDB, and exact infrastructure failures blank only the affected country; derived infrastructure and unexpected failures propagate. |
| HTTP JSON | 4 | 30 seconds per master batch | Exact deadline and saturation become Requests timeouts; broad startup failure and exact closure become connection errors; derived infrastructure, transport, and size errors retain their identities or families, an unusable declared charset becomes `UnknownEncodingError`, and every failure of the decode and parse phase itself becomes the boundary's own `ResponseDecodeError`. |
| ICMP RTT | 32 | 5 seconds per RTT batch | Expected probe and infrastructure failures become RTT `9999`; unexpected failures propagate so Core can retain the untouched adapter batch. |

Caller deadline, interruption, or close abandons a pending call and immediately recovers its slot; an abandoned running call remains worker-owned until it returns, and its late value or exception is discarded. Shutdown is two-phase: close begins for every service before any bounded join, and all joins share one original one-second deadline. A permanently blocked operation therefore consumes one service slot without delaying process exit; no replacement worker is started, and exhaustion makes that service fail fast until restart.

`launch_gtk.main()` closes the application's services exactly once after every attempted app path, through the `ApplicationServices` owner once construction reached it and otherwise through the owners construction had already built. Its invocation-local `body_completed` flag becomes true only after the protected body or its ordinary-`Exception` handler exits normally. Cleanup failure is suppressed while that flag is false, letting an uncaught caller `BaseException` resume implicitly with no launcher re-raise frame; ambient exceptions handled by callers do not affect this decision. An ordinary app `Exception` is printed once and selects `SystemExit(1)`, which also outranks cleanup failure. After a successful app path, a cleanup `BaseException` propagates unchanged.

`http_client` is one HTTPS policy boundary, one transport, and one failure classifier. `validate_https_url` accepts only exact `str` text that every URL parser reads identically (the shared `diagnostics` guard) and that splits into scheme `https` with a host and a parseable port; it returns that same text and rejects everything else, including non-`str` values, with the payload-free `HttpsPolicyError`. `open_https_response` opens one owned `requests.Session`, requests with `allow_redirects=False`, and follows at most five redirects itself: `301`, `302`, `303`, `307`, and `308` resolve their `Location` against the current URL and revalidate it under the same policy, redirect bodies close unread, and any other 3xx status, an absent `Location`, or a sixth redirect becomes a payload-free policy failure. Every hop's connect and read waits are clamped to the time the operation has left, and a wait the caller left absent becomes exactly that remainder, so no blocking wait can outlive the deadline. `get_json` validates the URL, then validates a supplied absolute deadline unchanged or computes and validates one 30-second default operation deadline, before registry lookup or pool startup, and runs one complete redirect chain and body inside one HTTP-pool operation: status validation, streaming through `iter_response_body` one transport read of at most 64 KiB at a time bounded by a 16 MiB default limit, response closure, character decoding, and JSON parsing. Deadline checks happen before pool startup, before every hop, after entering the response context, after every transport read, before decoding, and before parsing; each raises `requests.Timeout` directly, so expiry never surfaces a pool-internal type to a caller. The intentionally broad startup phase maps its initial raw `BaseException` to a fresh suppressed `requests.ConnectionError`. In the call phase, only exact deadline and saturation errors become fresh suppressed `requests.Timeout` values and only exact unavailability becomes a fresh suppressed `requests.ConnectionError`; derived and multiple-inheritance infrastructure errors propagate by identity. The declared charset is resolved to a codec before decoding, so every way of naming no usable codec is the payload-free `UnknownEncodingError`, and the decode and parse phase then owns every failure the body itself provokes: any `UnicodeError` from the decode, including the bare base class `idna` and `punycode` raise before CPython 3.14, and any `ValueError` or `RecursionError` from `json.loads`, including the bare `ValueError` of the integer string-digit limit and the recursion a deeply nested body exhausts, become the payload-free `ResponseDecodeError`. No body a single source sends can therefore reach a caller as an unclassified exception and defeat its per-source isolation. The Requests, HTTP, and size errors retain their original families and identities. A late response is entered and closed without reading after the caller has abandoned it, and late decoded values or errors are discarded by the pool. `describe_http_failure` maps one exception to an `HttpFailure` of kind, optional status code, and fixed `SafeDiagnostic`, and returns `None` for everything it does not own, including every pool abandonment, saturation, or unavailability error even under multiple inheritance, so infrastructure failures are never presented as endpoint failures. Two helpers give a caller the byte-granular control `Response.iter_content` cannot: `iter_response_body` yields the body one `raw.read1` at a time so a caller's own checks are reached within one read interval (both `get_json` and the GeoIP transfer read through it, so a trickling peer holds a pool slot or a download worker for at most one read interval past a check rather than a whole chunk), translating urllib3's transport failures into the Requests families the classifier owns exactly as `iter_content` does and falling back to `iter_content` where no `read1` exists; `shutdown_reads` shuts a response's read side down from another thread, the one interrupt that does not take the buffer lock an in-progress read holds, and reports whether a read side was there to shut down.

`diagnostics` holds the payload-free vocabulary the HTTP and adapter paths share. `SafeDiagnostic` carries one fixed text, `SafeDiagnosticError` declares exactly one for its subclasses, and `diagnostic_for_exception` returns a declared diagnostic or names only the exception type, never reading `args`, `str`, or `repr`. `safe_url` renders a configured URL as scheme, host, and port with any path replaced by `/<redacted>`, and returns `<invalid URL>` for anything that is not exact `str` text every parser reads identically, is not `http` or `https`, or carries no valid IP literal or DNS host; digit-and-dot hosts that are not IPv4 literals are deliberately rejected. `validate_https_url` applies that same character guard, so the policy and the transport parse identical bytes.

`geoip.Geolocation.countries_for` separates literal IPv4/IPv6 addresses from first-seen hostnames and resolves the complete hostname subset with exactly one DNS-pool batch under one five-second absolute deadline. Literals bypass DNS and reach MMDB unchanged. Ordered resolver outcomes use the first valid family-matching address; expected resolution, hostname encoding, exact deadline, exact saturation, exact closure, startup, or database failures blank only the affected country. Derived infrastructure outcomes propagate so the query fails without replacing old data. The DNS facade converts even the first startup `BaseException` into per-host unavailable outcomes and converts only exact map-phase unavailability; derived map errors and caller interruption propagate. Disabled geolocation remains `unknown`. A permanently blocked resolver retains one of the four DNS slots until it returns; exhausted capacity fails fast without replacement.

MMDB results are accepted only as mappings with an exact `str` flat `country_code`, or a mapping `country` containing an exact `str` `iso_code`. Malformed record shapes blank only the affected server's country; unexpected database method exceptions still propagate.

One `GeoIPDatabaseDownload` owns one transfer. It streams into a unique `0600` `mkstemp` sibling of its destination, so concurrent transfers never share a file and a partial database is never readable, and it opens the body through `http_client.open_https_response`, so the HTTPS-only redirect policy stays in one place. The absolute deadline the transfer is given can only shorten its own 120-second operation limit; every blocking read waits at most 15 seconds or the time that deadline leaves, whichever is smaller and never less than nothing, connecting waits at most five, and the boundary clamps each hop again. A peer that trickles bytes satisfies every read wait without ever completing a chunk or a header, so three mechanisms together hold the deadline against it. The body is read through `http_client.iter_response_body`, one transport read at a time, so the check before every write is reached within one read interval rather than once per completed 64 KiB chunk. A daemon watchdog armed for the remaining time before the response is opened — and cancelled when the transfer withdraws it — releases whatever the worker is waiting on through `http_client.shutdown_reads`, which shuts the connection's read side down instead of closing it, because closing takes the buffer lock the in-progress read holds. And the connect, status-line and header phases, equally byte-granular and with no response to interrupt yet, run on a daemon `_ResponseOpener` helper whose entered context the worker claims with a deadline-bounded wait; past that deadline the worker abandons the helper and returns, and the helper closes the response and session it eventually opens, installs nothing and writes no file, though it may outlive the transfer. Whichever checkpoint notices the deadline, the transfer reports exactly one payload-free `GeoIP download exceeded its time limit.` rather than a transport failure, and the enforced bound is the deadline plus the time one interrupted read needs to return. A declared `Content-Length` above 128 MiB is refused before one byte is read, and the streamed count is refused before the chunk that exceeds it is written. Cancellation and the deadline are checked before every write, before validation, and between validation and the atomic replacement, so a stopped transfer installs nothing it has not validated; a cancellation that arrives once that replacement has succeeded still reports the installed path, and the coordinator's own before-loading checkpoint decides whether it is loaded. Validation opens the temporary file as a MaxMind database and reads its metadata, so a truncated or non-mmdb body never reaches the cache. `cancel()` sets the transfer's flag and then releases whatever the worker is waiting on — the wait for a response the helper has not opened yet, or the read side of one it has — and returns without waiting for that worker, because its callers are main threads. Closing stays with the thread that owns the response: the worker's own context exit, or, only where a read side cannot be shut down, a detached daemon closer. That worker sees its own cancellation before it classifies the resulting failure, so a cancelled transfer reports nothing while a genuine transport, filesystem, or validation failure logs one payload-free diagnostic; a process with no thread to spare for the watchdog or the opener ends the transfer as the payload-free `_TransferHelperError` it is rather than as an unexpected exception. Progress callbacks run outside that lock, and the only file the transfer ever removes is its own temporary one, up until the replacement makes it the database.

## Adapters

`adapters.resolve_adapter(name)` is the sole Core resolution boundary for modules with `stat_master(game, game_info, master_list) -> list[Server]`. Under a short registration lock, an injected `adapter_table` entry wins before built-in lookup. A missing known `minetest`, `qstat`, or `rigsofrods` adapter is imported without holding that lock; importlib's per-module lock serializes its one module execution, including races with direct submodule imports. Same-thread package-attribute re-entry from loader execution receives the module whose import spec is still initializing and does not register it. After successful initialization, the registration lock protects `setdefault`, so an injection made during import wins final registration and every concurrent resolver returns that same registered object. Direct submodule imports are registered consistently on later resolution. Import failures leave no resolver state or registration and retry through importlib normally. An unknown resolver name raises `UnknownAdapterError`; package attribute access decides its own absent non-built-in names as normal `AttributeError`, so exceptions raised while a known loader executes propagate unchanged. Built-ins remain lazy, so importing one HTTP parser or the live-contract script does not initialize QStat or unrelated application paths.

`http_masters.collect_http_masters` gives Minetest and Rigs of Rods one ordered source policy. It computes one 30-second absolute deadline for the complete configured batch and passes that exact deadline to every source. URL-normalization and payload-adaptation `ValueError` failures are isolated only at their own phases; the fetch phase isolates exactly the failures `http_client.describe_http_failure` classifies, which never include pool abandonment, saturation, or unavailability. Requests-family errors from payload adaptation, unclassified fetch errors, other unexpected exceptions, and every non-`Exception` `BaseException` propagate unchanged. Successful source records retain configured order, a valid empty response counts as success, and a nonempty batch with no successful source raises the shared payload-free `AllMastersFailedError`. Every isolated source logs three payload-free parts: the adapter prefix, the translated master-failure message rendering the configured URL only through `safe_url`, and the fixed diagnostic for that failure (the classified `HttpFailure` diagnostic for a fetch failure, `Malformed master URL.` or `Malformed master payload.` for the two local phases).

- **qstat** — discovers `qstat` then `quakestat`, and runs it with its 10-second query timeout inside a 60-second monotonic parent deadline that `stat_master` computes once and `_run_qstat` applies to pumping the pipes, to the wait for a normal exit, and to failure cleanup. A nonblocking selector concurrently feeds stdin and drains stdout, discards stderr, and retains at most 16 MiB. The `qstat_processes.QStatProcessSupervisor` resolved per query (`get_qstat_process_supervisor`, replaceable through `install_qstat_process_supervisor`, importing neither Core nor the adapter) owns every handle from spawn registration to reap: spawn rejects admission once close has begun, registers a reservation under the supervisor lock, runs `Popen` outside it, and replaces the reservation with the handle under the lock, so a spawn that loses the race against close registers its child, kills it, retains it and raises `QStatSupervisorClosedError`. Cleanup on timeout, overflow, or error terminates, waits a fixed two-second grace or the remaining deadline, whichever is smaller, escalates to a kill, waits only the remaining deadline, and hands a child that outlived the bound to the supervisor's one lazy daemon reaper, which retains the handle until `poll()` or a finite `wait()` proves exit; no wait on a child is ever unbounded, a handle is released only after an observed exit, and a stop that fails is reported through a best-effort logger that swallows its own failure, so neither the stop nor its report can replace the query's primary exception. `begin_close` sends a kill to every registered child — a signal that cannot be delivered is tolerated, since the child stays retained either way — and retains it for reaping, `join_until(deadline)` validates its deadline and joins the reaper against it, and the reaper stops once close has left nothing registered and no spawn in flight; the enforceable contract is a bounded caller and application return with no lost handle while a child lives. Output is strictly decoded as UTF-8 and parsed into `Server` / `Player` records; discovery, process, size, decode, and malformed-XML failures are declared safe diagnostics (`QStatUnavailableError`, `QStatQueryError`), so Core logs their fixed, user-actionable text — a missing binary reads `Install QStat (qstat or quakestat) to query this game.` — instead of the exception type alone, while each keeps the `FileNotFoundError` or `RuntimeError` identity its callers check. UP-server player counts and limits are required nonnegative integers, including literal zero. Empty text and absent or empty rule/player sections become empty values; non-scalar text invalidates only its server entry. An empty response succeeds, a mixed response keeps valid records and logs one count-only malformed summary, and a nonempty response with no schema-valid records fails. Master entries and server records with exact status `DOWN`, `TIMEOUT`, or `ERROR` are schema-valid filtered records; missing, empty, or unknown server statuses are malformed. Master host order is preserved and de-duplicated (`dict.fromkeys`); QStat returns nothing if the last master times out.
- **minetest** — HTTPS JSON lists normalized into `Server` records without RTT or country enrichment. An empty list succeeds as `[]`, a mixed list keeps valid records and logs one count-only summary, and a nonempty list with no valid records fails only that master.
- **rigsofrods** — bounded HTTP JSON from the live API (`https://api.rigsofrods.org/server-list`). The request query is normalized to exactly one `json=true` parameter without disturbing unrelated raw query components or the fragment. Its malformed-entry policy matches Minetest. Each entry maps `verified` / `is-official` into `rules`, and `json-userlist` into `players`. The adapter does not perform RTT enrichment. Launch is the configured binary only (no config-file rewrite).

There is no proxy layer.

## Ping

`measure_rtt` materializes endpoints, returns empty batches without starting ICMP workers, and de-duplicates hosts in first-seen order. It uses a supplied absolute deadline unchanged or computes one five-second deadline, then passes that exact value through the shared finite-deadline validator before registry lookup or worker startup. It resolves the current ICMP pool dynamically, normalizes the separate startup phase, and calls `map_until` exactly once for the unique host batch. The complete one-request, one-second, unprivileged `icmplib` operation, including hostname resolution, runs in one of the 32 named daemon ICMP workers; it never nests a DNS-pool call or creates an executor. Exact deadline, saturation, unavailable-outcome, startup, map-closure, ICMP, socket, type, and value failures produce `9999`; derived infrastructure errors and other unexpected operation or map exceptions propagate so Core can fall back to the untouched adapter batch. Results expand to every original endpoint and server position, including duplicate hosts on different ports, while abandoned late outcomes cannot mutate returned maps or immutable replacement servers. `add_rtt_info` returns ordered replacement `Server` records rather than mutating adapter output, and Core is its sole enrichment caller.

## Launching

`build_launch_spec` resolves one launch's executable and working-directory context exactly once, against the activation directory its caller supplies, and dispatches through an explicit immutable pattern mapping (no dynamic `globals()` lookup) that also names the setting holding each pattern's binary — `steam_path` for Steam, `path` for the rest — and whether the configured game workdir applies at all. An empty or whitespace-only value in that setting is unconfigured input rather than a launch — the shipped defaults carry one such game — so it is rejected there with an actionable translated `ValueError` naming the game, synchronously in `Core.start_game` and before any worker exists, instead of reaching the executor as an empty `argv[0]`. A configured workdir is expanded and resolved against the activation directory first. Steam is the one pattern that ignores it: the shipped defaults pair `steam_launch` with a guessed game directory that need not exist, and the binary being spawned is the Steam client, so a Steam launch derives its cwd from the resolved `steam_path` (its parent, or the activation directory for a bare `steam`) and never from the game workdir. A bare command keeps its exact text so `PATH` lookup still applies; an absolute executable is used as written; a relative executable carrying a separator is resolved against the effective configured workdir, or against the activation directory when no workdir is set, because the child would otherwise resolve it a second time against its own directory. Both settings are read stripped, so a whitespace-only executable is the same unconfigured input an empty one is and a whitespace-only workdir is simply unset, rather than a command or a directory made of spaces that only fails inside `Popen`. The child cwd is the configured workdir when there is one, otherwise the resolved executable's parent, and the activation directory for a bare command; the executor exports `PWD` equal to that exact cwd for every pattern, because `Popen(cwd=…)` does not rewrite it and a client that reads `PWD` instead of asking the kernel would otherwise be told Obozrenie's own directory. Patterns return immutable `LaunchSpec` snapshots holding tuple arguments, that nonempty absolute cwd, environment overrides, and exact sensitive argument values; a specification cannot be constructed with a non-`str` cwd (`TypeError`) or a relative one (`ValueError`), the same exact-type/value split the records in `models` use. The executor logs only the redacted command, merges the specification's overrides onto a copy of the process environment, and starts the client detached in the specification's cwd. Only the executable and working directory are snapshot-based, so the executor consults no ambient working directory; the child environment is the process environment plus that `PWD` and those overrides, which win over it, and the HL2 pattern deliberately extends the inherited `LD_LIBRARY_PATH` rather than replacing it. Every executor failure diagnostic replaces all declared sensitive values while the original exception object is returned to Core; a specification failure raises to the caller instead, which redacts before display.

## UI

GTK 4 and libadwaita (`gi`), over a presentation tier that has neither. `presenter.MainPresenter` decides everything the main window shows and does; `gtk_window.MainWindow` — an `Adw.ApplicationWindow` composite template built from `data/ui/main_window.ui` — shows it, and `App` owns it as `window`. `presenter.MainView` is the whole of what the presenter may ask of a window: reads (`browser_game`, `connect_game`, `host_text`, `password_text`, `sidebar_shown`, `filter_values`, `selected_server`), writes (`set_games`, `set_servers`, `select_browser_game`, `select_connect_game`, `set_host_text`, `show_sidebar`, `show_page`, `set_error_text`, `set_action_enabled`, `refilter`), and the three dialog presentations. The presenter never receives a widget, so the behaviour suites drive it over a fake view with no display at all.

The window reports each user action by calling one presenter notification through `_notify`, and never reports a write the presenter asked for: every such write runs under the `_syncing` flag `_write` sets — `set_servers` and `refilter` included, even though both can drop the current selection. A user's own action clearing that selection is reported; a presenter-requested refill that drops it is not. `attach_presenter` is what starts the reporting, so the selections `load_games` and `bind_settings` make while the window is being set up reach no notification; the first rendering is then requested explicitly through `render_loaded_state`, which shows the welcome page and reports the sidebar, the filters, and the Connect data, but deliberately not the browser game — so the welcome page stays until the user picks a game or presses refresh. That page is also the stack's first child in `main_window.ui`, so a window that is never rendered still opens on it rather than on an empty server list. The browser game is the window's own state (`_browser_game`): the sidebar `Gtk.ListView` and the compact `Gtk.DropDown` both show it and are re-synced after every change, so a search that hides the selected row does not lose it. The Connect game is the connect drop-down's own selection.

`list_rows` turns each domain record into a `GObject.Object` carrying data only — `GameRow` (id, name, icon, status icon), `ServerRow` (the record plus every value a cell renders, including the flag emoji derived from the ISO country code), `PlayerRow` — and `gtk_lists` holds the `Gtk.SignalListItemFactory` cells that render them; the views decide which icon a boolean becomes. The player-count text the server list and the information dialog both show is formatted only in `presenter.players_text`, so that translated message has one formatting site. Servers run `Gio.ListStore` → `Gtk.FilterListModel` over a `Gtk.CustomFilter` that defers to the presenter's `server_matches` → `Gtk.SortListModel` over the column view's own sorter → `Gtk.SingleSelection`, the initial sort is Ping ascending, and `set_servers` is one `splice`. Games are one store behind three selectors: the sidebar list, through a case-insensitive substring `Gtk.StringFilter` on `name` driven by the search entry; the compact drop-down; and the connect drop-down, the one selector whose cells omit the status icon. That status icon changes while a row is on screen, so its cell follows the row through a `notify::status-icon` handler the unbind disconnects rather than copying the value once at bind.

Preferences and Refresh follow the valid browser-game selection, while Connect follows a valid independent Connect-game selection plus a canonical explicit-port endpoint; Info additionally requires that endpoint to match a listed server. Refresh is disabled while the browser query is working. All four come from `derive_action_sensitivity`, which reads no view state and mutates none. Query presentation changes only after Core admits the request; a rejected racing duplicate leaves the current page and status icon alone but re-derives all four sensitivities from current `GameTable` state, and a synchronously completed admission is never rendered as working. Completion performs the same derivation, and a selected-game error page displays only the exact sanitized stored query error, escaped for the Pango markup an `Adw.StatusPage` description is parsed as. Action handlers repeat their own game, endpoint, query, and server validation. Both Connect paths — the button and the information dialog's own — read the current password entry only when invoked. Launch and query worker callbacks schedule all GTK work through `GLib.idle_add`; displayed launch details replace the transient raw password with `***`. Selecting a server copies its host and game into the Connect controls, and because that copy is a presenter-requested write the window reports nothing, so the presenter issues the one Connect-data notification it deserves itself.

Every activation calls `present()` on the main window and nothing else: GTK 4 widgets are visible unless a document says otherwise, so there is no visibility boilerplate to declare and nothing to show a second time. An activation that finds no window returns at once, because GIO emits `activate` even for a startup that failed and quit before it built one. One App-owned admission flag permits a single startup-dialog idle dispatcher. That dispatcher presents the one-shot settings-recovery warnings in order, each dialog's close continuing the chain so they never stack, and then asks the GeoIP coordinator to offer; admission is released by the coordinator's completion callback, or at once when the coordinator refuses the offer, never merely because the window is up. Overlapping activations add no dispatcher and only present, while an activation after completion can offer again.

Errors are an `Adw.AlertDialog` (`gtk_dialogs.present_error`) with one Close response whose `response` signal runs the optional close callback — the chain the startup warnings walk. Server information is `ServerInfoDialog`, an `Adw.Dialog` template built from `data/ui/server_info_dialog.ui`, whose Connect closes the dialog before calling back, because that callback re-validates and may launch a game. Preferences is `gtk_preferences.PreferencesDialog`, built entirely from the presenter's `PreferenceField`s — an `Adw.EntryRow`, an `Adw.SwitchRow`, or a framed `Gtk.TextView` per `OptionKind` — where Save writes every option back and closes and closing any other way discards. About is a `Gtk.AboutDialog` carrying the packaged logo texture: `Adw.AboutDialog` accepts only icon-theme names and the icon theme cannot serve a zip-backed package resource, so this one dialog is deliberately not a libadwaita one.

Game selectors and the Secure filter are keyboard-focusable, the sidebar search entry and both game drop-downs search displayed names, and adjacent filter labels provide marked mnemonics for their controls.

`launch_gtk` selects the toolkit before it builds anything. After the macOS re-exec and before it imports the GTK tier, `_require_toolkit()` requires `Gtk` 4.0 and `Adw` 1 and refuses a GTK below 4.14 or a libadwaita below 1.5 (`TOOLKIT_FLOOR`) with a translated `ToolkitVersionError`; a missing typelib raises `gi.require_version`'s own `ValueError` there, and `main()`'s one printed-error path ends the run as exit 1 either way. Importing `obozrenie.gtk` inside `main()` is what keeps importing the launcher free of the toolkit entirely. It then constructs the `GameTable`, the `Geolocation`, `Core`, the `GeoIPDownloadCoordinator` (over that same `Geolocation`), the `ApplicationServices` owner, `Settings`, and `App` in that order, and hands the owner to App as `services`. The owner holds Core, the coordinator, the QStat process supervisor, and the three network pools; those services stay purpose-specific and the owner adds only two-phase shutdown. `begin_close` marks them closing in the order Core, GeoIP, QStat, DNS, HTTP, ICMP, visiting every owner even after one of them fails and preserving the first `BaseException`; only then does `join_until` join all six against one unchanged validated deadline. `close_until` validates that deadline before anything closes and raises the first failure of either phase, so a malformed deadline cannot half-close the application. An owner whose `begin_close` raised is not recorded complete, so a repeated close retries exactly that owner and no other. `App.on_shutdown` calls `begin_close` from a `finally` around the settings save, and the launcher's own `finally` calls `close_until` against a fresh one-second deadline (`_APPLICATION_SHUTDOWN_TIMEOUT_SECONDS`), so the join phase still runs when GTK's shutdown handler failed and both calls together close nothing twice. PyGObject prints and swallows whatever a `startup` or `shutdown` handler raises, so neither handler raises: `App.__init__` gives the application its `status` and an empty `handler_failure` before anything can fail, each handler records the first failure as a payload-free `diagnostic_for_exception` and reports it once through `helpers.log_safe_diagnostic`, and `main()` selects `SystemExit(1)` for a recorded failure exactly as it does for an app-path `Exception` — outranking a cleanup failure, which stays suppressed. The recorder sets the failure before it reports it, and the shared logger swallows a report that fails, because the failure being recorded is often the log stream itself and `on_startup` quits the application on the line after the call. Only the settings save is inside the shutdown handler's recorded block: the `Shutting down` line that follows a successful save sits outside it, so a log write failing there is printed and swallowed by the dispatch rather than turned into a failed run. Construction that fails before the owner exists closes the process-wide services the launch never built — the QStat supervisor and the three pools, which exist with their modules — followed by whatever it did build, in those same two phases. Detached game clients stay outside this ownership.

The `GeoIPDownloadCoordinator` is the only owner of the offer dialogs and their transfer. It reaches them through one injectable seam, `GeoIPOfferDialogs`, so the whole state machine runs with no display in the behaviour suite. `present_question(parent, on_accept, on_decline)` presents an `Adw.AlertDialog` that closes itself on any response and routes `download` to acceptance and everything else — including its close response — to decline; the `QuestionDialog` handle it returns can `dismiss()` the question without answering it, disconnecting the response handler first because libadwaita's `force_close()` still emits the close response on an `Adw.AlertDialog`. `present_transfer(parent, on_cancel)` presents a `TransferDialog` whose `can-close` is off, so its Cancel button, its close button, and Escape all arrive as a cancellation rather than a close; the handle's own `close()` force-closes it without cancelling and is idempotent, which is how completion closes a dialog it must not also cancel.

`offer(parent, finished_callback)` returns true only when it presented a new question, and then promises exactly one later callback: after a decline, or after an accepted transfer's dialog has closed and any downloaded database has been loaded. It returns false and promises nothing when a database is already loaded, when the coordinator is closing, or while an offer, its transfer, or that transfer's worker is still live. One state lock publishes the transfer dialog, transfer, worker, closing, and completion flags, and dialog work, the caller's callback, and thread joins never run under it. The question itself is never coordinator state: it answers itself through acceptance or decline, and only the `offer` call that presented it can have to dismiss it. Acceptance presents the transfer dialog, then builds the transfer immediately before the single daemon worker that runs it, so the transfer's 120-second window opens with the work rather than with the offer. A decline during that transfer cancels it and closes the dialog, leaving completion to that worker, so a running transfer keeps exactly one completion owner. Completion closes the dialogs, loads the database, and only then calls back. `begin_close` cancels the transfer, which closes the response its worker may be reading; the worker re-checks closing before it queues anything through `GLib.idle_add`, and every queued progress and completion callback re-checks it again, so a transfer that outlives close neither loads a database nor touches a widget. `join_until(deadline)` joins that worker for the remaining time only.

## Data

Runtime settings, UI templates, icons, desktop integration sources, and
catalogs have one canonical source tree at `obozrenie/data` and are read through
Python package-resource streams. The desktop entry and two hicolor application
icons are also installed as OS integration files from those canonical sources.
Writable user settings remain filesystem files under `~/.config/obozrenie`,
alongside the sibling `~/.config/obozrenie.lock` that serializes them.

The gettext domain is `me.vorotnikov.Obozrenie`. Automatic selection
(`translation()` with no argument) reads the first nonempty of `LANGUAGE`,
`LC_ALL`, `LC_MESSAGES`, `LANG`, in that order, preserving each variable's
colon-separated chain; normalization, duplicate suppression, and C/POSIX
termination are unchanged, `LC_CTYPE` is never consulted, and an explicit
`languages=` argument never reads the environment. The selected MO stream is
loaded into one module-level `GNUTranslations` object used by both Python
strings and the two template documents. Before a document reaches
`Gtk.Template`, Python parses the XML, translates every explicitly marked
property, attribute, or `GtkStringList` `<item>`, and removes the marker so
GTK cannot translate it again. Every string a template shows lives in those
documents, `GtkStringList` `<item>` elements included; Python keeps only the
strings it formats or builds in code, including the ones the dialogs it
constructs itself carry. No native gettext
domain or locale filesystem path is bound. Babel and PyYAML are development-only dependencies; the runtime and its
unittest modules consume only the packaged MO.

## Delivery

CI builds one canonical wheel and source distribution on Linux, outside the
checkout, and transfers that exact pair to every artifact consumer. Archive
checks require exact member sets recalculated from the current checkout rather
than pinned member counts, safe paths and member types, semantically checked
generated metadata (`METADATA`, `PKG-INFO`, `WHEEL`, `setup.cfg`, and the
egg-info directory), exact wheel `RECORD` hashes and sizes, licensing,
catalogs, runtime data, and the three operating-system integration files. The
source distribution must rebuild a wheel with the same contract.

One canonical checkout source-byte map — every package module, every packaged
data file, every classified runtime and source-only test, and `COPYING`,
`README.md`, and `pyproject.toml`, all read from the working tree — is the
identity every shipped source member must satisfy. The direct wheel and the
wheel rebuilt from the source distribution must reproduce every package Python
and data member of that map, plus the three operating-system integration
copies, which equal their canonical package resources; the source distribution
must reproduce every package, shipped-test, and root source file. Each archive
is compared over its whole source region — everything outside the wheel's
`dist-info` directory, everything outside the source distribution's generated
root metadata and egg-info directory — so a member with no checkout
counterpart, such as a module deleted after the build, is rejected rather than
skipped. Runtime tests extracted from the source distribution must equal the
currently classified checkout tests before the extraction directory is
created. The installed and custom-prefix fixtures validate both artifacts
against the map before creating a virtual environment, so a stale artifact and
a stale extracted suite can never validate each other. `RECORD` is verified
for internal integrity before the checkout comparison, so an adversarial
artifact that keeps the project name, version, and metadata while regenerating
a valid `RECORD` over mutated or added payload bytes is still rejected, and
the failure names the archive type and the exact mismatched path.

Widgets need a display, so every Linux `unittest` command runs under
`xvfb-run -a`, and the jobs that build widgets set `GSK_RENDERER=cairo` and
`GDK_BACKEND=x11`; macOS runs in its own session and needs no wrapper. The two
template documents are validated by instantiating them, because
`gtk4-builder-tool validate` cannot resolve a libadwaita template parent.

Linux tests the installed wheel on Python 3.11 through 3.14, and macOS tests it
on the workflow's explicit Python version with Homebrew's library directory on
the loader path. Tests run from a neutral directory, extract the runtime suite
from the supplied source distribution, and prove package and resource origins
belong to the installed wheel rather than the checkout. A separate clean
custom-prefix installation derives its purelib path and proves the same origin
and resource contracts without satisfying the project from an existing
installation.

Ordinary push and pull-request jobs use deterministic fixtures and never
require live services. The weekly schedule alone runs bounded HTTPS schema
contracts for Minetest and Rigs of Rods with one initial attempt, at most two
transient retries, production parsers, a script deadline, and pool cleanup; it
does not run GTK, QStat, RTT, GeoIP, or launch paths. A retry follows only a
timeout, a non-TLS connection failure, a response-integrity failure, a decode
failure, or HTTP 429, 500, 502, 503, or 504; every other outcome, including
TLS, invalid-request, HTTPS-policy, size, permanent status, unclassified,
and pool failures, fails after one attempt. `uv.lock` remains ignored
and untracked, and workflows use maintained major action tags rather than
immutable action revisions. Container build and delivery are not supported.
